- Python (issue #937): `simulate(p, damage=False)` builds an Option the way `ovd fill --as-new` does and returns the results of `ovd run`. A key left out takes the Defaults Profile value, where it meant "the engine before that input existed". A required input left out (`cargo`, `hull_form`, `formation`, `length_overall_m`, `beam_m`, `service_area`) is an error that names it; no starter value is used. The old names (`loa_m`, `depth_m`, `freeboard_min_m`, `eta_d`, `speed_max_kn`, `lightship_k_t_per_m3`, `channel`, `vessel`, `self_propelled`, `atb`) and the glossary names are both accepted. `cb`, `midship_coefficient`, `ruleset` and the six `crew_*` keys are refused, each with its reason. An input that does not apply to the Cargo, Containment, Formation or `when` value raises, where it was ignored. A Cargo the Containment cannot carry raises `TypeError`, where it returned `{"error": ...}`. A dict that uses an old name and no `hull_form` is built as `raked_box`, and one with neither `formation` nor a flag as a pushed barge; a dict in glossary names must give both, as a file must. The result gains `rule_trace`, `cost`, `calibration`, `gross_tonnage`, `crew`, `rooms`, `stern_arrangement`, `spaces`, `gas_fuel`, `holding_time`, `damage_status` and the convoy, lock and pusher blocks. Damage stability is off by default: pass `damage=True`. The Python API page is `docs/python-api.md`. No saved file, the app or `ovd run` moves. The calibration of the installed-power factor still calls the old engine entry; a follow-up re-fits it on the new path.
