- The 3D model and `ovd export` show the arrangement the results report, issue #1041. The Vessel Model came from a run of its own that skipped damage, so on a stack that screens by IGC 2.7 damage it showed the unscreened pick while the results and `ovd draw` showed the screened one (on the 140 x 29 x 12 m coastal LNG reference design: 2 x 2 tanks of 13.28 m in the model, 2 x 3 of 13.38 m in the results). The model now comes from the results' own run, at that run's stage. `ovd export` runs damage, as `ovd run` and `ovd draw` do (glTF about 15 s on the reference design, was about 3 s), except for an STL or OBJ with no `--below`: that is the hull alone, the same at both stages when the depth is typed and not optimised (`optimise_depth`), so it skips the damage search (a depth that follows the tank, because it is not typed, runs it). `ovd export --no-damage` skips damage and gives the unscreened model, as `ovd run --no-damage` does; it is about 2 to 3 times the time of `ovd export` on main for a glTF, because the model now comes from a run that settles the deckhouse rooms and lets the search choose tanks along (main's model ran neither). The app's 3D model, and the web build's model export, are of the stage the results show: the unscreened pick until damage runs (the web export runs no damage then), then the damage run's pick while it still matches the Option's inputs. The damage run hands back the Vessel Model of its own pick with its results, and the session keeps it beside them, so the page builds the screened 3D model from it with no second damage search (the web worker passes it as JSON; the desktop app keeps it the same way). `ovd mesh --hash` stays the unscreened stage, the app's first evaluation.
